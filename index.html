Input validation policy

The backend should reject unsupported or non-satellite inputs rather than converting ordinary camera photos into cyclone predictions. Source, timestamp and geolocation metadata can be used as provenance signals when available.

Design principle: “No evidence, no claim.” Missing source metadata is displayed as missing instead of being guessed.

System overview

STRIDE — Satellite-based Tropical Risk & Intelligence

STRIDE is an SIH-oriented cyclone intelligence prototype that brings satellite-image validation, cyclone identification, classification and future prediction into one transparent workflow. The frontend is deliberately structured around provenance: source data, model output, historical data and external operational maps are visually separated.

01 • Validate

Accept recognised image formats and send the observation to the production validation layer.

02 • Identify

Return the cyclone/no-cyclone decision supplied by the ML service.

03 • Classify

Display class and confidence only when returned by the trained model.

04 • Predict

Expose current intensity and track fields only when model/data inputs support them.

05 • Explain

Keep raw model output visible for technical demonstrations and judge verification.

06 • Protect

Fail closed when the model or source feed is unavailable; never substitute fake predictions.

Prototype note: STRIDE is not an official warning service and must not be used as the sole basis for safety-critical decisions.
